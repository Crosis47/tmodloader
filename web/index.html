Release notes
Update workflow

    

  • Check for updates: Looks for a newer release. No downloads, backup or restart.
    • 

  • Restart game and apply updates: Clears any update hold, saves and stops the game, then runs the steps below. Players disconnect; the dashboard stays online. Saved settings drafts are not applied.
    • 



    

  1. Download: Fetch the selected tModLoader release.
    2. 

  2. Create a recovery checkpoint: Copy worlds, mods, mod configs and saved settings before changing live data. Keep the previous runtime for recovery.
    3. 

  3. Test: Download mod updates into a separate copy and check that enabled mods, dependencies and the copied world load successfully.
    4. 

  4. Apply and verify: Switch only after the test passes, then start the real game and check its health.
    5. 



If something fails: Download or compatibility failures keep the existing runtime and mods. If the updated game fails its startup health check, the previous runtime and checkpoint data are restored automatically and updates are paused. If recovery cannot start the game, the dashboard stays available for troubleshooting.


The checkpoint stays on the data volume; it is not an archive in the Backups list. Startup checks cannot guarantee every mod works throughout gameplay.


    

  • Restore previous runtime and data: Queues recovery. Restart game and restore checkpoint performs it, reverting progress since that checkpoint. Current data is kept temporarily during recovery. After the restored game passes its health check, both recovery copies are deleted automatically. Your dashboard login is preserved.
    • 

  • Delete recovery checkpoint: Permanently removes the current recovery copy and its logs to free space. Your running world, mods and cached runtimes remain. You cannot restore that checkpoint afterward.
    • 

  • Cancel recovery: Cancels the queued restore. Any update hold stays in place. It does not restart the game.
    • 

  • View diagnostics / Release notes: Opens recorded update logs or the upstream release details. Neither changes the server.
    •

            Server password
            Change the password players use to join. Save as a draft, then apply to restart the game.
            Managed in Compose
            Container ports and mounts and configuration mode are managed through Compose or environment variables. Edit those settings and recreate the container to apply changes.
            Manage the Steam Web API key on the Workshop page and mod configuration files on the Mod configs page. The admin token is created during dashboard setup; resetting it requires access to the container.
            

            Mod configuration files
            Edit existing UTF-8 configuration files in tModLoader/ModConfigs. Files appear after mods generate their configuration. Saving writes directly to disk, separately from the settings draft. Restart the server to ensure mods load the changes. Syntax checks follow the file extension: JSON, YAML, TOML, INI, or XML. Other extensions use text mode without format-specific validation. Each mod determines which values it supports.
            

            Interactive console
            Enter tModLoader server commands such as help, playing, save, or say Hello everyone. This is the game console, not a Linux shell. Commands act immediately, unlike staged settings.
